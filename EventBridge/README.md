# Amazon EventBridge

**Amazon EventBridge** is a fully managed, **serverless event bus** for building **event-driven architectures**. Producers emit **events** (JSON documents describing "something happened"), EventBridge matches them against **rules**, and **routes** them to **targets**. It is the evolution of **CloudWatch Events** (same API and underlying service, with more features). Anything you did with CloudWatch Events is now EventBridge.

```
 Event sources                    Event bus                 Rules (pattern match)        Targets
 ─────────────                    ─────────                 ─────────────────────        ───────
 AWS services     ──┐                                    ┌─► Rule A ──► Lambda
 Custom apps      ──┼──►  [ default / custom / partner ] ┼─► Rule B ──► SQS, SNS, Step Functions
 SaaS partners    ──┘          (events, JSON)            └─► Rule C ──► Another bus / API destination
```

- **Push-based**, **near real time**, **at-least-once** delivery, **loosely coupled**: producers don't know the consumers.
- **Regional**. Pay **per event** published (AWS service events on the default bus are **free**).
- Compared to **SNS** (pub/sub fan-out to subscribers) and **SQS** (queue, pull): EventBridge adds **content-based routing** with rich filtering, **schema registry**, **SaaS integrations**, **scheduling** and **replay**.

## Core Concepts

| Concept | What it is |
|---|---|
| **Event** | JSON with metadata (`source`, `detail-type`, `account`, `region`, `time`) and a free-form **`detail`** payload. Up to **256 KB**. |
| **Event bus** | The channel that receives events. Has its own **resource policy**. |
| **Rule** | Attached to **one bus**. Either an **event pattern** (match events) or a **schedule**. Up to **5 targets** per rule. |
| **Target** | What is invoked on a match. Optionally with **input transformation** (reshape the event), a **DLQ** and **retry policy**. |
| **Event pattern** | JSON filter on the event content (exact match, prefix, suffix, numeric, `anything-but`, `exists`, `$or`, IP ranges...). |

```json
{
  "source": ["aws.ec2"],
  "detail-type": ["EC2 Instance State-change Notification"],
  "detail": { "state": ["terminated"] }
}
```

### Anatomy of an event

Every event has the same **envelope** (metadata added by EventBridge or the producer) and a **`detail`** object with the actual payload.

```json
{
  "version": "0",
  "id": "6a7e8feb-b491-4cf7-a9f1-bf3703467718",
  "detail-type": "EC2 Instance State-change Notification",
  "source": "aws.ec2",
  "account": "111122223333",
  "time": "2026-11-21T10:15:30Z",
  "region": "eu-north-1",
  "resources": ["arn:aws:ec2:eu-north-1:111122223333:instance/i-0abc123"],
  "detail": {
    "instance-id": "i-0abc123",
    "state": "terminated"
  }
}
```

| Field | Meaning |
|---|---|
| **`version`** | Event schema version (always `"0"` for now). |
| **`id`** | Unique event ID, generated by EventBridge. |
| **`detail-type`** | Human-readable **type** of event. Used together with `source` to identify it. |
| **`source`** | **Who emitted it**. AWS services use `aws.<service>` (`aws.ec2`, `aws.s3`). Custom events use your own name (reverse-DNS style, e.g. `com.myapp.orders`). The `aws.` prefix is **reserved**. |
| **`account`** | **Account ID** of the producer. |
| **`time`** | When the event occurred (**UTC**, ISO 8601). |
| **`region`** | Region where the event originated. |
| **`resources`** | **ARNs** of the resources involved (can be empty). |
| **`detail`** | **Free-form JSON** payload, specific to the event type. Your custom data goes here. |

- **Custom events**: send with `PutEvents` (up to **10 events** per call). You set `source`, `detail-type` and `detail` (**required**, as a JSON string), optionally `resources` and `time`. EventBridge fills in the other fields.
- **Rules match on any of these fields**, usually `source`, `detail-type` and keys inside `detail`. The pattern's structure **mirrors the event**, and every listed value is an **array** (OR within a field, AND across fields).
- **Schema registry** can discover these schemas and generate code bindings.

## Event Buses

| Bus | Purpose |
|---|---|
| **Default bus** | Exists in every account and Region. Receives events from **AWS services** automatically. |
| **Custom bus** | For your **own applications**. Separate permissions, rules and archives. |
| **Partner event bus** | Receives events from **SaaS partners** (Zendesk, Datadog, Auth0, Shopify...). |

- **Cross-account / cross-Region**: a rule can target **another event bus** (resource policy must allow it). Useful for **centralized** event buses.
- **Archive and replay**: store events (optionally filtered) and **replay** them later, for **debugging**, **recovery** or **testing** new consumers.
- **Schema registry**: automatically **discovers** event schemas and generates **code bindings** (Java, Python, TypeScript).

## Rules and Targets

- **Targets** (20+ AWS services): **Lambda**, **SQS**, **SNS**, **Kinesis**, **Step Functions**, **ECS tasks**, **Batch**, **CodePipeline/CodeBuild**, **SSM** (Run Command, Automation), **CloudWatch Logs**, **API Gateway**, **another event bus**, and **API destinations**.
- **API destinations**: call any **HTTP endpoint** (SaaS or on-prem) with auth (API key, OAuth, basic) and **rate limiting**.
- **Input transformer**: pick fields from the event and build a custom payload for the target.
- **Retry and DLQ**: if delivery fails, EventBridge **retries** (default up to **24 hours / 185 attempts**) with backoff, then can send to an **SQS DLQ**.
- **Permissions**: the rule needs an **IAM role** (or the target needs a **resource policy**, e.g. Lambda) to invoke the target.

## Scheduling

| Feature | Use |
|---|---|
| **Scheduled rules** (legacy) | **Cron** or **rate** expression on the **default bus**. Minimum **1 minute**. |
| **EventBridge Scheduler** (recommended) | Dedicated service: **one-time** or **recurring** schedules, **time zones**, **flexible time window**, **millions** of schedules, **270+** target APIs. |

- Typical use: run a **Lambda every 5 minutes** (`rate(5 minutes)`) or a **nightly job** (`cron(0 2 * * ? *)`).
- Schedules are **at-least-once** and not guaranteed to the exact second.

### Schedule expressions

Three formats (the `at()` one only in **Scheduler**):

| Type | Syntax | Use |
|---|---|---|
| **Rate** | `rate(value unit)` | **Fixed interval**: `rate(5 minutes)`, `rate(1 hour)`, `rate(7 days)`. |
| **Cron** | `cron(min hour day-of-month month day-of-week year)` | **Specific times** and calendars. |
| **One-time** | `at(yyyy-mm-ddThh:mm:ss)` | **Run once** at a given moment (Scheduler only). |

**Rate**
- Unit is `minute(s)`, `hour(s)` or `day(s)`. Use the **singular** when the value is **1** (`rate(1 minute)`, not `rate(1 minutes)`) and the **plural** otherwise. Minimum is **1 minute**.

**Cron** has **6 fields** (note: **not** the 5 of Unix cron, and there is a **year**):

```
cron( 0  2  *  *  ?  * )
      │  │  │  │  │  └─ year          (1970-2199)
      │  │  │  │  └──── day-of-week   (1-7 or SUN-SAT)
      │  │  │  └─────── month         (1-12 or JAN-DEC)
      │  │  └────────── day-of-month  (1-31)
      │  └───────────── hours         (0-23)
      └──────────────── minutes       (0-59)
```

| Wildcard | Meaning |
|---|---|
| `*` | **Every** value of the field. |
| `,` | List (`MON,WED,FRI`). |
| `-` | Range (`9-17`). |
| `/` | Step (`0/15` = every 15 starting at 0). |
| `?` | **No specific value**. **Required** in either day-of-month **or** day-of-week. |
| `L` | **Last** (last day of the month, last Friday `6L`). |
| `W` | Nearest **weekday** to a given day (`15W`). |
| `#` | **Nth** weekday of the month (`3#2` = second Tuesday). |

- **Day-of-month and day-of-week can't both be set**: one of them must be `?`.
- **Examples**: `cron(0 8 * * ? *)` daily at 08:00 · `cron(0/15 * * * ? *)` every 15 min · `cron(0 18 ? * MON-FRI *)` weekdays at 18:00 · `cron(0 9 1 * ? *)` first day of each month at 09:00.
- **Time zone**: **scheduled rules** always use **UTC** (no daylight saving adjustment). **Scheduler** lets you pick a **time zone**, which also handles **DST**.
- Cron is **more flexible** than rate: use `rate` for "every N minutes", `cron` for **calendar-based** schedules.

## EventBridge Pipes

**Pipes** connect a **source** to a **target** **point-to-point**, with optional **filtering**, **enrichment** (Lambda, API Gateway, Step Functions) and **transformation** in between.

```
Source (SQS, Kinesis, DynamoDB Streams, MSK, MQ) ─► Filter ─► Enrichment ─► Target
```

- Replaces custom **glue Lambda** code. **Ordering** is preserved for ordered sources.
- Unlike rules on a bus, a pipe has **one source** and **one target**.

## Common Event Sources (examples)

- **EC2** state changes, **Auto Scaling** events, **ECS** task state changes.
- **S3** object events (enable EventBridge notifications on the bucket), with richer filtering than native S3 notifications.
- **CloudTrail** API calls (any API call becomes an event), e.g. "alert when someone creates an IAM user".
- **GuardDuty**, **Security Hub**, **Config**, **Health** events and **CodePipeline** state changes.
- **CloudWatch alarms** state changes.

## EventBridge vs. SNS vs. SQS

| | **EventBridge** | **SNS** | **SQS** |
|---|---|---|---|
| Model | **Event bus** + rules | **Pub/sub** topics | **Queue** |
| Delivery | Push | Push | **Pull** |
| Filtering | **Rich content-based** patterns on the whole event | Filter policies on attributes or body | None |
| Targets | 20+ AWS services, HTTP, other buses | Lambda, SQS, HTTP, email, SMS, push, Firehose | Consumers poll |
| SaaS sources | **Yes** (partner buses) | No | No |
| Scheduling | **Yes** | No | Delay only |
| Replay | **Yes** (archive) | No (FIFO topics have archive/replay) | No |
| Throughput | High (soft quotas per Region) | Very high | Nearly unlimited |
| Buffering | No (retries up to 24 h) | No | **Yes** (up to 14 days) |

- **EventBridge → SQS**: a common combination. The queue **buffers** events for consumers at their own pace.
- **Choosing**: react to **AWS / SaaS events** or need **routing and filtering** → EventBridge. Very high-volume **fan-out** or **mobile / email / SMS** → SNS. **Buffer and decouple** workers → SQS.

## EventBridge and CloudWatch

- **CloudWatch Events = EventBridge** (same service, the console redirects).
- **CloudWatch alarm state changes** are events on the default bus, so an alarm can trigger any target, not only SNS and Auto Scaling.
- Rules can target **CloudWatch Logs** to **store events** for later search with Logs Insights.

## Security and Cost

- **IAM** controls who can `PutEvents`, manage rules and read buses. **Bus resource policies** grant **cross-account** access.
- **Encryption** at rest with AWS-owned or **customer-managed KMS** keys. HTTPS in transit. **VPC interface endpoints** (PrivateLink) available.
- **Cost**: per **custom / partner / cross-account event** published (**64 KB** chunks), plus **archive**, **replay**, **Pipes** requests, **Scheduler** invocations and **API destination** calls. **AWS service events** on the default bus are **free**.

## Exam Tips (SAA)

- **React to an AWS event** (EC2 stopped, S3 upload, API call in CloudTrail) → **EventBridge rule** → Lambda / SNS / Step Functions.
- **Run something on a schedule** (cron) → **EventBridge** (Scheduler or scheduled rule), not a server running cron.
- **Receive events from a SaaS provider** → **partner event bus**.
- **Centralize events across accounts or Regions** → send them to **another event bus** in a central account.
- **Replay past events** → **archive and replay**.
- **Event-driven decoupling** with filtering and routing → EventBridge. Need a **buffer** → add **SQS** as target.
- **Who did what** → **CloudTrail**. EventBridge reacts to the CloudTrail events, it doesn't record them.
- **CloudWatch Events** in the exam text means **EventBridge**.
